# M8.2 boot-regression diagnosis

## Restored M1 boot

The M8.1 bounded boot regression came from a command-line divergence, not from
the M8.1 APFS image or trustcache. The failed invocations packed machine options
inside one double-quoted `-machine` argument and retained literal single quotes
around `args='...'`. The guest did not recognize `wlan-olyhal-abort`; its serial
log entered the AppleOLYHAL AMFM path and stalled before root mount.

The successful historical form uses separate legacy options, an unquoted shell
argument for `-args`, `-m 8G`, and `-nographic -serial mon:stdio`:

```sh
qemu-system-aarch64 -M darwin \
  -bootkc boot/bootkc -dtree boot/dtree -sptm boot/sptm -txm boot/txm \
  -ramdisk RAMDISK -tc TRUSTCACHE \
  -args 'rd=md0 serial=3 -v -noprogress wdt=-1 wlan-olyhal-abort' \
  -m 8G -nographic -serial mon:stdio
```

With this form, serial output explicitly records
`AppleOLYHAL::start: found wlan-olyhal-abort boot-arg, bailing`, mounts md0,
and reaches `bash-5.3#` around guest time 21 seconds.

## Gate 2 runtime result

Case D ran `/usr/local/bin/openios-m8-smoke`; AMFI logged
`allow process-exec*`. Dyld then rejected the first smoke version:

```text
dyld[4]: missing LC_LOAD_DYLIB (must link with at least libSystem.dylib)
Abort trap: 6              /usr/local/bin/openios-m8-smoke
OPENIOS_M8_SMOKE_STATUS=134
```

This is a loader-format failure after authorization, not a trustcache or AMFI
rejection.

## M8.2 Gate 2 result

The build script now uses a local `.tbd` that declares only the install name
and version read from the matching ramdisk's `libSystem.B.dylib`; it declares
no invented symbols. `-needed_library` produces:

```text
/usr/lib/libSystem.B.dylib (compatibility version 1.0.0, current version 1356.0.0)
```

The new M8.2 binary is ad-hoc signed with CDHash
`1eb24f5b7ba35d3eddff67bcc4d7121a5ae982c5`. Its copied trustcache is v1 with
468 entries and includes this CDHash. The binary was inserted into the separate
`m8.2-libsystem-20261029` disposable APFS image, whose catalogue and mounted
copy both have SHA-256
`63b8dd1d534c0f725d8397cb67c3b0ac708f3f4ff3abf28148f18a610c786db3`.

Using the exact historical command form, the guest reached `bash-5.3#`; AMFI
logged `allow process-exec* /usr/local/bin/openios-m8-smoke`; and the program
printed its direct-syscall diagnostic before returning:

```text
openios-m8-smoke: signed Mach-O diagnostic\nOPENIOS_M8_2_SMOKE_STATUS=0
```

The `\n` is literal output from this first assembly smoke payload, not a
serial formatting artifact. Gate 2 is therefore **PASS**: execution and exit
status are verified, with no AMFI, dyld, or trustcache rejection.

## M9 runtime baseline

The existing guest `/usr/sbin/ioreg` was executed after Gate 2. AMFI allowed
the exec, but dyld rejected it before any IORegistry query:

```text
dyld[4]: Library not loaded: /usr/lib/libncurses.5.4.dylib
Reason: tried: '/usr/lib/libncurses.5.4.dylib' (no such file, no dyld cache)
OPENIOS_IOREG_STATUS=134
```

This is a runtime dependency-closure blocker for the existing `ioreg`, not
evidence about AppleASCWrapV6 matching, probing, or start. The restore image
catalogue lacks this ncurses path, and a custom inspector also needs verified
IOKit/CoreFoundation runtime libraries and ABI headers. No synthetic registry
output or unsupported declaration was introduced.
